# vulnetix_detection_rule_feed (Resource)

A curated feed of virtual patches, countermeasures and catalogue rules, published to a public URL for IDS, IPS, WAF, SIEM and YARA engines and the Vulnetix runtime sensor to fetch. A feed has one output format, because its consumers each read one. The plan sets how many feeds of each format a tenant may have, and a feed holds at most 500 rules. Name entries, a selector, or both. The format cannot be changed on the server, so a changed format is applied as delete and create, which moves the feed's URL.

Manages the `DetectionRuleFeed` config kind through `/config/objects/DetectionRuleFeed/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (most of them, such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object, or lets go of it for a kind the server never deletes (such as `Organization`). Some kinds wait on a person after they are applied (an invited `Member`, a Slack connection): `status.phase` says so, and Terraform does not wait.

## Example Usage

### Minimal

The arguments the kind requires, and nothing else.

```terraform
# Only the arguments the kind requires. From config-schemas examples/DetectionRuleFeed/minimal.yaml.

resource "vulnetix_detection_rule_feed" "edge_waf" {
  name = "edge-waf"
  entries = [
    {
      rule       = "9c2d4e6f-1a3b-4c5d-8e7f-0a1b2c3d4e5f"
      rule_table = "virtual_patch"
      rule_type  = "AWS_WAF"
    },
  ]
  format = "AWS_WAF"
}
```

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/DetectionRuleFeed/advanced.yaml.

resource "vulnetix_detection_rule_feed" "edge_suricata" {
  name         = "edge-suricata"
  description  = "Block-lane Suricata rules for exploited edge appliance CVEs, fetched by the perimeter IPS."
  display_name = "Edge Suricata virtual patches"
  entries = [
    {
      cve        = "CVE-2024-3400"
      rule       = "4d5e6f7a-8b9c-4d0e-9f1a-2b3c4d5e6f7a"
      rule_table = "virtual_patch"
      rule_type  = "SURICATA"
    },
    {
      cve        = "CVE-2023-46805"
      disabled   = true
      rule       = "5e6f7a8b-9c0d-4e1f-8a2b-3c4d5e6f7a8b"
      rule_table = "virtual_patch"
      rule_type  = "SURICATA"
    },
  ]
  format         = "SURICATA"
  publish        = true
  schema_version = 1
  selector = {
    when = "kind == 'SURICATA' && (kev || epss >= 0.5) && cvss >= 7.0 && falsePositiveRisk != 'HIGH' && now - published < duration('8760h')"
  }
  labels = {
    engine = "suricata"
    team   = "netsec"
  }
  annotations = {
    consumer = "Suricata sensors at the edge pull this feed every 15 minutes."
  }
}
```

## Schema

### Required

- `format` (String) The output format, and so which rules the feed accepts. SNORT_YARA publishes snort.rules and rules.yar from the third-party catalogue together. SNORT, SURICATA, MODSECURITY, NGINX, AWS_WAF, CLOUDFLARE_WAF and REGEX_L7 are block-lane virtual patches; SIGMA, YARA, STIX and OPENIOC are detect-lane countermeasures. Every published feed also carries rules.json and a signed manifest for the runtime sensor. One of `SNORT_YARA`, `SNORT`, `SURICATA`, `MODSECURITY`, `NGINX`, `AWS_WAF`, `CLOUDFLARE_WAF`, `REGEX_L7`, `SIGMA`, `YARA`, `STIX`, `OPENIOC`.
- `name` (String) The object's name (`metadata.name`), unique per kind within the tenant. Changing it replaces the object.

### Optional

- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `description` (String)
- `display_name` (String) The feed's name. Defaults to metadata.name.
- `entries` (Attributes Set) Rules named one by one. Each is checked to exist when it is added and again at publish. (see [below for nested schema](#nestedatt--entries))
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.
- `publish` (Boolean) true: publish on apply, and again whenever the entries change, to the feed's public URL. false: keep the feed a draft; a published feed is revoked, which deletes its published files. Schema default: `false`.
- `schema_version` (Number) The layout of the published files. Schema default: `1`.
- `selector` (Attributes) Rules chosen by a condition, as well as any entries. Each time the feed is built for publishing, the condition is evaluated against the generated rules of the feed's format (virtual patches for a block-lane format, countermeasures for a detect-lane one), once for each vulnerability a rule was written for, and a rule is included when it holds for any of them. The third-party catalogue (SNORT_YARA) carries no vulnerability data, so it takes entries only. A published feed holds at most 500 rules, explicit entries first. (see [below for nested schema](#nestedatt--selector))
