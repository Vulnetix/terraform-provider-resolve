# vulnetix_member (Resource)

A person in the organisation, by email address, with their role. Applying a Member for someone who is not yet in the organisation sends them an invitation, the same one the members page sends; the object then reports phase Pending, with the invitation's expiry, until they sign in and accept it. A role change on a member takes effect at once; on a pending invitation it replaces the invitation. Deleting the document revokes an outstanding invitation, or removes the member: their account is deactivated and kept for the audit trail, and they lose access to the organisation. Applying needs an owner or admin. An apply that would leave the organisation without an owner, or remove the person applying, is refused.

Member decides who can act for the tenant, so it can only be applied by an owner or admin of the organisation, and a role above the caller's own cannot be granted. A member is refused with HTTP 403.

Manages the `Member` config kind through `/config/objects/Member/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (most of them, such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object, or lets go of it for a kind the server never deletes (such as `Organization`). Some kinds wait on a person after they are applied (an invited `Member`, a Slack connection): `status.phase` says so, and Terraform does not wait.

## Example Usage

### Minimal

The arguments the kind requires, and nothing else.

```terraform
# Only the arguments the kind requires. From config-schemas examples/Member/minimal.yaml.

resource "vulnetix_member" "alice" {
  name  = "alice"
  email = "alice@acme.com"
}
```

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/Member/advanced.yaml.

resource "vulnetix_member" "alice" {
  name  = "alice"
  email = "alice@acme.com"
  role  = "owner"
  labels = {
    team = "security"
  }
  annotations = {
    ticket = "https://tracker.example.com/ACCESS-42"
  }
}

resource "vulnetix_member" "bob" {
  name  = "bob"
  email = "bob@acme.com"
  role  = "member"
}

resource "vulnetix_member" "carol" {
  name  = "carol"
  email = "carol@acme.com"
  role  = "developer"
}
```

## Schema

### Required

- `email` (String) The person's email address, in lower case. It identifies the member and cannot change: to replace one person with another, delete this document and declare a new one. A document for someone who is already a member, or already invited, takes them over under this name.
- `name` (String) The object's name (`metadata.name`), unique per kind within the tenant. Changing it replaces the object.

### Optional

- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.
- `role` (String) owner, developer or member. developer can plan, apply and export every kind except Organization, Member, ServiceAccount and VaultEntry, and cannot manage members, invitations, billing, the vault or service accounts. Only an owner may grant owner or developer. admin is the retired role: a member who already holds it keeps it while the document says admin, but no apply grants it. One of `owner`, `developer`, `member`, `admin`. Schema default: `member`.

### Read-Only

- `id` (String) The object's name, the same as `name`.

### Nested Schema for `status`

Read-Only:

- `authorization_url` (String) Where a person authorizes the object while the phase is `AwaitingAuthorization`.
- `extra` (Map of String) Other fields the kind reports, such as an invitation's expiry or a service account's principal. Structured values are JSON.
- `message` (String) Why the object is in its phase, when the server says.
- `object_uuid` (String) The object's id on the server.
- `once` (Map of String, Sensitive) Credentials the server shows only when it creates the object: a service account's `apiKey` and `secret`, a messaging connection's `signingSecret`, a log source's ingest token. They are kept in the state from the create, so keep the state encrypted. They cannot be read again: replace the object to get new ones.
- `phase` (String) `Applied` for most objects. `Pending` when the object waits on someone (an invited member who has not accepted), `AwaitingAuthorization` when a person has to authorize it in a browser at `authorization_url`. Terraform does not wait for either. `Unmanaged` means the object exists but no manager owns it.
