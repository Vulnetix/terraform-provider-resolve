# vulnetix_quality_gate (Resource)

The tenant's quality gate: the checks every vulnetix scan in CI must pass. When a check is set here it overrides the matching scan flag; a check left out leaves the flag in charge. One per tenant.

Manages the `QualityGate` config kind through `/config/objects/QualityGate/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (most of them, such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object, or lets go of it for a kind the server never deletes (such as `Organization`). Some kinds wait on a person after they are applied (an invited `Member`, a Slack connection): `status.phase` says so, and Terraform does not wait.

## Example Usage

### Minimal

The arguments the kind requires, and nothing else.

```terraform
# Only the arguments the kind requires. From config-schemas examples/QualityGate/minimal.yaml.

resource "vulnetix_quality_gate" "default" {
}
```

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/QualityGate/advanced.yaml.

resource "vulnetix_quality_gate" "default" {
  block_malware  = true
  block_unpinned = true
  cooldown_days  = 7
  eol = {
    block = true
    severities = {
      next_quarter   = "skip"
      retired        = "critical"
      this_quarter   = "low"
      within_30_days = "high"
    }
  }
  exploits = "active"
  sca_autofix = {
    max_major_bump = 1
    strategy       = "stable"
  }
  severity    = "high"
  version_lag = 1
  labels = {
    team = "platform-security"
  }
  annotations = {
    ticket = "https://jira.example.com/browse/SEC-2212"
  }
}
```

## Schema

### Optional

- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `block_malware` (Boolean) Fail when a dependency is known malware. Overrides --block-malware.
- `block_unpinned` (Boolean) Fail on a dependency declared without a pinned version. Overrides --block-unpinned.
- `cooldown_days` (Number) Fail on a dependency version published fewer than this many days ago. Overrides --cooldown.
- `eol` (Attributes) End-of-life policy. A dependency whose product reaches end of life inside a horizon is reported at that horizon's severity; skip reports nothing for that horizon. (see [below for nested schema](#nestedatt--eol))
- `exploits` (String) Fail on a vulnerability with an exploit at or beyond this maturity. Overrides --exploits. One of `poc`, `active`, `weaponized`.
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.
- `name` (String) The object's name. QualityGate is one per tenant, so it is always `default`.
- `sca_autofix` (Attributes) How vulnetix fix and scan --sca-autofix choose a target version. (see [below for nested schema](#nestedatt--sca_autofix))
- `severity` (String) Fail on any affected vulnerability at or above this severity. Overrides --severity. One of `low`, `medium`, `high`, `critical`.
- `version_lag` (Number) Fail on a dependency whose installed version is among this many most recently published versions of its package: 1 fails on the newest release, 3 on any of the three newest. It holds back releases too fresh to trust, and is not a check for being out of date. 0 turns it off. Overrides --version-lag.

### Nested Schema for `eol`

Optional:

- `block` (Boolean) Fail the scan on end-of-life dependencies. Overrides --block-eol. It decides only whether the CLI fails: once a tenant has any stored quality gate, the server writes an end-of-life finding at the horizon severity for every scanned dependency that reaches end of life inside a horizon not set to skip, whatever this says. The CLI reads the horizon severities only when this, or --block-eol, is true.
- `severities` (Attributes) The severity given to a dependency by how close its end of life is. skip ignores that horizon. (see [below for nested schema](#nestedatt--eol--severities))

<a id="nestedatt--sca_autofix"></a>
### Nested Schema for `sca_autofix`

Optional:

- `max_major_bump` (Number) The most major versions a fix may cross: 0 keeps fixes within the current major, N allows up to N. Any whole number from 0 up, with no upper limit. The --sca-autofix-max-major-bump flag also takes a negative number for no limit, but the gate cannot store one, and a value set here overrides the flag, so a tenant that wants no limit leaves this out.
- `strategy` (String) latest: the newest release. safest: the release with the fewest known vulnerabilities. stable: the newest release past its cooldown. rolling: the newest release that is not malware, known vulnerabilities allowed. One of `latest`, `safest`, `stable`, `rolling`.

Read-Only:
