# vulnetix_risk_strategy (Resource)

A risk prioritisation strategy: an ordered list of rules that puts every open finding in a priority tier. A finding's tier is the position of the first rule it matches, 0 being the highest priority. A tenant may keep several strategies; one is active, and a tenant with none active uses the system default.

Manages the `RiskStrategy` config kind through `/config/objects/RiskStrategy/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (most of them, such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object, or lets go of it for a kind the server never deletes (such as `Organization`). Some kinds wait on a person after they are applied (an invited `Member`, a Slack connection): `status.phase` says so, and Terraform does not wait.

## Example Usage

### Minimal

The arguments the kind requires, and nothing else.

```terraform
# Only the arguments the kind requires. From config-schemas examples/RiskStrategy/minimal.yaml.

resource "vulnetix_risk_strategy" "catch_all" {
  name = "catch-all"
  rules = [
    {
      metric   = "REMAINING"
      operator = "ALWAYS"
    },
  ]
}
```

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/RiskStrategy/advanced.yaml.

resource "vulnetix_risk_strategy" "exploit_first" {
  name        = "exploit-first"
  active      = true
  description = "Known exploitation first, then exposure, then score."
  rules = [
    {
      label    = "Malware"
      metric   = "MALWARE"
      operator = "IS_TRUE"
    },
    {
      label    = "CISA KEV"
      metric   = "KEV_CISA"
      operator = "IS_TRUE"
    },
    {
      enabled  = true
      metric   = "EXPLOIT_WEAPONIZED"
      operator = "IS_TRUE"
    },
    {
      label    = "Exposed package"
      metric   = "INTERNET_EXPOSED_PACKAGE"
      operator = "IS_TRUE"
    },
    {
      attack_path_id = "0b9d5f9e-3c51-4a0f-9d43-6f1f5f0c2a11"
      label          = "Edge to database"
      metric         = "ATTACK_PATH"
      operator       = "IS_TRUE"
    },
    {
      label  = "Reachable and likely"
      metric = "CEL"
      when   = "reachable && (epss >= 0.2 || exploitMaturity == 'active')"
    },
    {
      metric        = "EPSS"
      operator      = "GTE"
      threshold_low = 0.1
    },
    {
      metric         = "CVSS"
      operator       = "BETWEEN"
      threshold_high = 10
      threshold_low  = 7
    },
    {
      enabled  = false
      label    = "Public PoC"
      metric   = "EXPLOIT_POC"
      operator = "IS_TRUE"
    },
    {
      label    = "Everything else"
      metric   = "REMAINING"
      operator = "ALWAYS"
    },
  ]
  labels = {
    team = "platform-security"
  }
  annotations = {
    ticket = "https://jira.example.com/browse/SEC-2214"
  }
}
```

## Schema

### Required

- `name` (String) The object's name (`metadata.name`), unique per kind within the tenant. Changing it replaces the object.
- `rules` (Attributes List) The rules in priority order: the first is tier 0. Exactly one REMAINING rule is required, and it belongs last, where it catches every finding no earlier rule matched. (see [below for nested schema](#nestedatt--rules))

### Optional

- `active` (Boolean) Make this the tenant's active strategy. Activating one deactivates the others, so at most one document in a set should say true. Schema default: `false`.
- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `description` (String)
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.

### Read-Only

- `id` (String) The object's name, the same as `name`.
- `status` (Attributes) What the server says about the object beyond its spec. (see [below for nested schema](#nestedatt--status))

<a id="nestedatt--rules"></a>
### Nested Schema for `rules`

Required:

- `metric` (String) What the rule tests. Present-or-not signals: MALWARE; KEV_CISA, KEV_ENISA, KEV_VULNETIX, KEV_VULNCHECK (in that known-exploited catalogue); EXPLOIT_WEAPONIZED, EXPLOIT_ACTIVE, EXPLOIT_POC; INTERNET_EXPOSED_PACKAGE (the package was seen on a publicly reachable cloud resource of the repository); INTERNET_EXPOSED (the repository has a publicly reachable cloud resource); REACHABLE and UNREACHABLE (SCA reachability, assessed); TRACEABLE (resolves to a file and lines); TRACEABLE_GRAPH (traceable, and the file is called in the repository graph); ATTACK_PATH (matches attackPathId). Scores: CVSS and CWSS (the effective score, an analyst override preferred), CUSTOM_CVSS and CUSTOM_CWSS (the override only), CESS (0 to 10), EPSS (0 to 1). REMAINING matches everything. CEL matches when the when expression is true. One of `MALWARE`, `KEV_CISA`, `KEV_ENISA`, `KEV_VULNETIX`, `KEV_VULNCHECK`, `EXPLOIT_WEAPONIZED`, `EXPLOIT_ACTIVE`, `EXPLOIT_POC`, `INTERNET_EXPOSED_PACKAGE`, `INTERNET_EXPOSED`, `REACHABLE`, `UNREACHABLE`, `TRACEABLE`, `TRACEABLE_GRAPH`, `ATTACK_PATH`, `CVSS`, `CWSS`, `CUSTOM_CVSS`, `CUSTOM_CWSS`, `CESS`, `EPSS`, `REMAINING`, `CEL`.

Optional:

- `attack_path_id` (String) ATTACK_PATH only, and required there: the attack path the rule matches.
- `enabled` (Boolean) Schema default: `true`.
- `label` (String) The tier's name in the console. Defaults to the metric and operator.
- `operator` (String) IS_TRUE for a present-or-not metric. GTE, GT, LTE and LT compare a score with thresholdLow; BETWEEN tests thresholdLow <= score <= thresholdHigh. ALWAYS matches everything, for REMAINING. One of `IS_TRUE`, `GTE`, `GT`, `LTE`, `LT`, `BETWEEN`, `ALWAYS`.
- `threshold_high` (Number)
- `threshold_low` (Number)
- `when` (String) The condition of a CEL rule, over the finding variables. A CEL expression, evaluated in the `finding` environment.
