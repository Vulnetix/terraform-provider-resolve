# vulnetix_scanner_profile (Resource)

Which scanners the Software Factory runs, the SLSA level its builds must reach, and the evidence it keeps. One per tenant. These are the security.scanners, security.scanners.custom, security.slsa_min and security.evidence settings of the factory settings document: applying saves a new revision of that document, with one audit entry per changed setting, and a FactorySettings document never carries them, so the two kinds never write the same setting. A field left out means its default. Deleting the document puts all four settings back to their defaults.

Manages the `ScannerProfile` config kind through `/config/objects/ScannerProfile/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (most of them, such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object, or lets go of it for a kind the server never deletes (such as `Organization`). Some kinds wait on a person after they are applied (an invited `Member`, a Slack connection): `status.phase` says so, and Terraform does not wait.

}

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/ScannerProfile/advanced.yaml.

resource "vulnetix_scanner_profile" "default" {
  custom   = ["sca", "malscan", "secrets", "sast"]
  evidence = "sbom_only"
  scanners = "custom"
  slsa_min = "L2"
  labels = {
    team = "security"
  }
  annotations = {
    ticket = "https://tracker.example.com/SEC-210"
  }
}
```

### Reference

Every kind's reference file is also in [Vulnetix/platform-iac-examples](https://github.com/Vulnetix/platform-iac-examples), with the same document as YAML.

```terraform

```

## Schema

### Optional

- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `custom` (List of String) The scanner ids to run when scanners is custom; required then, and kept but unused otherwise. The security.scanners.custom setting. Schema default: `[]`.
- `evidence` (String) The evidence kept for a build. cdx_slsa: a CycloneDX SBOM and SLSA provenance. sbom_only: the SBOM alone. The security.evidence setting. One of `cdx_slsa`, `sbom_only`. Schema default: `cdx_slsa`.
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.
- `name` (String) The object's name. ScannerProfile is one per tenant, so it is always `default`.
- `scanners` (String) The scanners a factory scan runs. minimum: software composition analysis, malware and secrets. all: every scanner. custom: the scanners listed in custom. The security.scanners setting. One of `minimum`, `all`, `custom`. Schema default: `minimum`.
- `slsa_min` (String) The lowest SLSA build level the factory accepts for what it builds. The security.slsa_min setting. One of `L1`, `L2`, `L3`. Schema default: `L3`.
