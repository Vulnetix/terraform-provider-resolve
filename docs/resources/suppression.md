# vulnetix_suppression (Resource)

A suppression rule: findings that match its scope are suppressed, now and in every later scan, until it expires. Every apply writes the suppression audit. Rules created from a VexSource are owned by that source and cannot be declared here.

Manages the `Suppression` config kind through `/config/objects/Suppression/{name}`. Applies are recorded with the provider's `manager`, so a GitOps `vulnetix config apply --prune` leaves this object alone.

Most kinds merge: an argument removed from the configuration is no longer managed, and keeps its last value on the server. A kind that is wholly declared (such as `ApiSpecSource`, `RiskStrategy` and `VexSource`) is replaced instead: a removed argument goes back to its default. Destroying the resource deletes the object.

## Example Usage

### Minimal

The arguments the kind requires, and nothing else.

```terraform
# Only the arguments the kind requires. From config-schemas examples/Suppression/minimal.yaml.

resource "vulnetix_suppression" "lodash_prototype_pollution" {
  name = "lodash-prototype-pollution"
  scope = {
    rule = "CVE-2021-23337"
  }
  type = "risk_accepted"
}
```

### Advanced

Every argument the kind supports. A secret is a write-only `*_wo` argument fed from an ephemeral variable, so it never reaches the plan or the state; change `*_wo_version` to send a new value.

```terraform
# Every argument the kind supports. From config-schemas examples/Suppression/advanced.yaml.

resource "vulnetix_suppression" "lodash_template_not_reachable" {
  name          = "lodash-template-not-reachable"
  expires       = "2027-06-30T00:00:00Z"
  justification = "vulnerable_code_not_in_execute_path"
  reason        = "lodash.template is never called with user input; the build only renders static templates."
  scope = {
    branch     = "main"
    category   = "sca"
    line       = 1204
    line_range = "1204-1210"
    path       = "web/package-lock.json"
    purl       = "pkg:npm/lodash@4.17.20"
    repository = "acme/storefront"
    rule       = "CVE-2021-23337"
    target     = "pkg:npm/lodash"
  }
  type = "false_positive"
  when = "severity != 'critical' && !kev && repo == 'acme/storefront'"
  labels = {
    team = "payments"
  }
  annotations = {
    ticket = "https://jira.example.com/browse/SEC-1234"
  }
}
```

## Schema

### Required

- `name` (String) The object's name (`metadata.name`), unique per kind within the tenant. Changing it replaces the object.
- `scope` (Attributes) What the rule matches. It must name at least one of rule, target or path; a rule that names none would match everything. Every field given must match. (see [below for nested schema](#nestedatt--scope))
- `type` (String) The decision: false_positive (the finding is wrong), wont_fix, risk_accepted, mitigated (a control outside the code covers it) or deferred. One of `false_positive`, `wont_fix`, `risk_accepted`, `mitigated`, `deferred`.

### Optional

- `annotations` (Map of String) Free key/value notes for people and tools (`metadata.annotations`), such as a ticket link.
- `expires` (String) When the rule stops applying. Left out, it never expires; reports flag it once it goes unreviewed for the RemediationPolicy suppressionReviewMaxAgeDays.
- `justification` (String) Why the product is not affected, in the OpenVEX vocabulary, for VEX documents minted from this rule. One of `component_not_present`, `vulnerable_code_not_present`, `vulnerable_code_not_in_execute_path`, `vulnerable_code_cannot_be_controlled_by_adversary`, `inline_mitigations_already_exist`.
- `labels` (Map of String) Free key/value labels (`metadata.labels`). Stored with the object, never interpreted by the server.
- `reason` (String) Why, for the people who review suppressions.
- `when` (String) An extra condition a finding must meet, over the finding variables. A CEL expression, evaluated in the `finding` environment.

### Read-Only

- `id` (String) The object's name, the same as `name`.

### Nested Schema for `scope`

Optional:

- `branch` (String)
- `category` (String) The finding category. crypto and ai are inventory components (a CBOM algorithm, certificate, key or library; an AIBOM agent, SDK, model or service), which match on target. One of `sast`, `secrets`, `iac`, `container`, `sca`, `license`, `malware`, `crypto`, `ai`.
- `line` (Number) A line in path.
- `line_range` (String) A range of lines in path.
- `path` (String) A file path, relative to the repository root.
- `purl` (String) Only findings in this package. Without a version, every version.
- `repository` (String) A repository by its full name, owner/name as the forge shows it. Nested groups (group/subgroup/name) are allowed.
- `rule` (String) The vulnerability or rule id: a CVE or other advisory id, or a SAST, IaC or secrets rule id.
- `target` (String) An inventory component's identity: an algorithm SPDX id, a certificate subject, a purl or a model name.
